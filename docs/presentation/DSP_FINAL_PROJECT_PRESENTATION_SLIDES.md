## 🗣️ 1. ที่มาของปัญหาในชีวิตจริง (Real-World Problem)

### ทำไมเวลาเราคุย Discord หรือ Zoom ถึงได้ยิน "เสียงสะท้อนของตัวเอง"?
* **ความจริงเชิงอะคูสติกส์:** ปัญหา **ไม่ได้อยู่ที่เครื่องเรา** แต่อยู่ที่ **"เพื่อนเปิดลำโพงทิ้งไว้โดยไม่ใส่หูฟัง"**
* **วงจรอุบาทว์ของเสียงสะท้อน (The Acoustic Loop):**
  1. เราพูดใส่ไมค์เรา ➔ เสียงส่งผ่านอินเทอร์เน็ตไปดังออก **"ลำโพงของเพื่อน"** ($x[n]$)
  2. เสียงลอยสะท้อนโต๊ะ กำแพง เพดานในห้องเพื่อน ($h[n]$) ➔ มุดเข้า **"ไมค์ของเพื่อน"** ($d[n]$)
  3. ไมค์เพื่อนดูดเสียงเราย้อนกลับมาเข้าหูเรา!

```
[ตัวเรา (Far-End)] ----(ส่งเสียงผ่านเน็ต)----> [ลำโพงของเพื่อน]
       ^                                            |
       |                                       (สะท้อนในห้อง h[n])
       |                                            v
(ได้ยินเสียงสะท้อนตัวเอง) <---(ส่งย้อนกลับ)-- [ไมค์ของเพื่อน] <--- [เสียงเพื่อน (Near-End)]
```

* **ระบบ AEC ต้องติดตั้งที่ไหน?:** ต้องฝังอยู่ใน **เครื่องของเพื่อน** เพื่อดักตัดเสียงเราทิ้งก่อนส่งกลับมา

## 🧠 ผลกระทบทางจิตวิทยา: Delayed Auditory Feedback (DAF)

### ทำไมเวลาได้ยินเสียงตัวเองสะท้อน คนเราถึงต้องหยุดพูด?
* **วิทยาศาสตร์การได้ยิน (Psychoacoustics):** เมื่อสมองมนุษย์ได้ยินเสียงพูดของตัวเองย้อนกลับมาล่าช้าประมาณ **$50 - 200\text{ ms}$** จะเกิดอาการ **Delayed Auditory Feedback (DAF)**
* ระบบการควบคุมการออกเสียงของสมองจะเกิดความสับสน ลิ้นพันกัน สะดุด และหยุดพูดโดยอัตโนมัติ
* **AEC จึงเป็นระบบที่คอขาดบาดตาย:** หากไม่มีระบบ AEC มนุษย์จะไม่สามารถสื่อสารแบบเปิดลำโพง (Hands-free) บนสมาร์ตโฟนหรือแอปประชุมออนไลน์ได้เลย!

## 🔍 2. การสำรวจข้อมูล (EDA) & ทำไมตัวกรองดั้งเดิมถึงสอบตก?

### การพิสูจน์ปัญหาการทับซ้อนของสเปกตรัม (Spectral Overlap)
* ทั้งเสียงพูด Far-End ($x[n]$) และเสียงสะท้อน ($d[n]$) ต่างเป็น **เสียงมนุษย์เหมือนกัน**
* พลังงานทั้งหมดกระจุกตัวอยู่ในย่านเดียวกันเป๊ะ ($100\text{ Hz} - 4,000\text{ Hz}$)

```
   [ผลการทดสอบตัวกรองความถี่คงที่ (Classical LTI Filters) ใน main.ipynb]
   1. Lowpass Filter (< 500 Hz)   : ตัดเสียงสะท้อนสูงได้ แต่เสียงคนพูดกลายเป็น "เสียงอู้อี้ในโอ่ง"
   2. Bandstop Filter (300-1500Hz): เนื้อเสียงแหว่งเว้า บิดเบี้ยว แต่เสียงก้องย่านอื่นยังคงอยู่ครบ
```

## 🎯 3. การค้นพบทาง DSP: การตรวจจับความหน่วงเวลา (Bulk Delay)

### ปัญหา Time-of-Flight ในอากาศ
* ลำโพงกับไมค์อยู่ห่างกัน คลื่นเสียงเดินทางด้วยความเร็ว $343\text{ m/s}$ ทำให้เกิดความหน่วงเวลา (Delay)
* หากไม่ชดเชยดีเลย์ ตัวกรองปรับตัวได้จะต้องเสียค่าน้ำหนัก (Filter Taps) ไปกับช่วงความเงียบ ทำให้ลู่เข้าไม่ได้

### วิธีแก้: ค้นหาจุดเริ่มต้นเสียงสะท้อนด้วย Cross-Correlation อัตโนมัติ
$$r_{dx}[k] = \sum_n d[n] \, x[n-k] \quad \longrightarrow \quad k^* = \arg\max |r_{dx}[k]|$$

```
  Normalized Correlation
   1.0 |                   จุดยอด Peak: ตรวจพบ Lag = 122 จุด (7.64 ms)
       |                        *
       |                       / \
   0.0 +--------+-------------/---\------------------> Lag (samples)
       0        20           122  200
```
✅ **ผลลัพธ์:** ชดเชยสัญญาณอ้างอิงล่วงหน้า ($x[n - k^*]$) ทำให้ตัวกรองเริ่มทำงาน ณ จุดเกิดเหตุทันที

## 🏗️ 4. สถาปัตยกรรมระบบ (DSP Pipeline Architecture)

เราออกแบบโครงสร้างระบบตาม **DSP Blueprint 5 สเตจ** ที่ได้รับคำแนะนำจากอาจารย์:

```
[ Stage 1: Ingestion ] ──> แปลงสัญญาณเสียง Far-End x[n] และ Mic d[n] เข้าสู่ 16 kHz
         │
[ Stage 2: Delay Check] ──> คำนวณ Cross-Correlation ค้นหา Bulk Delay (k* samples)
         │
[ Stage 3: Compensation] ──> เลื่อน Buffer สัญญาณอ้างอิงล่วงหน้า x_aligned[n]
         │
[ Stage 4: NLMS Engine]  ──> ประมาณค่าเสียงก้อง y[n] = w^T * x แล้วหักล้าง e[n] = d[n] - y[n]
         │                   ปรับค่าน้ำหนักด้วยไดนามิกสเกล: w[n+1] = w[n] + (mu / ||x||^2) * e * x
         │
[ Stage 5: Evaluation ] ──> ประเมินค่า ERLE (dB) และส่งสัญญาณเสียงสะอาด e[n] ออกสู่ระบบ
```

## 🧠 หัวใจทางคณิตศาสตร์: Standard LMS vs Normalized LMS

เราเขียนอัลกอริทึมทั้ง 2 ตัวด้วย **Pure NumPy** บนพื้นฐานคณิตศาสตร์โดยตรง:

### 1. Standard LMS (Least Mean Squares)
$$\mathbf{w}[n+1] = \mathbf{w}[n] + \mu \, e[n] \, \mathbf{x}[n]$$
* **ข้อจำกัด:** $\mu$ เป็นค่าคงที่ ถ้าคนพูดตะโกนเสียงดัง พลังงาน $\|\mathbf{x}[n]\|^2$ พุ่งสูง จะทำให้ตัวกรอง **หลุดลอยและระเบิด (Diverge)**

### 2. Normalized LMS (NLMS - พระเอกของโครงงาน)
$$\mathbf{w}[n+1] = \mathbf{w}[n] + \frac{\mu}{\|\mathbf{x}[n]\|^2 + \epsilon} \, e[n] \, \mathbf{x}[n]$$
* ปรับอัตราการเรียนรู้ตามพลังงานขณะนั้นโดยอัตโนมัติ
* **เสถียร 100%:** เสียงจะเบาหรือดัง ตัวกรองก็ไม่หลุด และมีความเร็วในการลู่เข้า (Convergence Speed) สูงกว่ามาก

## 🧪 6.1 การทดลองสถานการณ์ที่ 1 (S1: คนเดียว ห้องคงที่)

**เงื่อนไข:** มีเฉพาะเสียงลำโพงสะท้อนในห้อง ไม่มีคนพูดหน้าไมค์ ($v[n] = 0$) เป้าหมายคือ **ตัดจนเงียบสนิท**

### การวัดผลด้วยค่า ERLE (Echo Return Loss Enhancement):
$$\text{ERLE} = 10 \log_{10} \left( \frac{E[d^2[n]]}{E[e^2[n]]} \right) \quad (\text{dB})$$

```
================================================================================
📊 สรุปผลการประเมินค่า ERLE ในสถานการณ์ S1:
1. Standard LMS                     :  9.05 dB   (ลู่เข้าช้า ยังมีเสียงก้อง)
2. NLMS (ไม่ชดเชย Delay)            : 14.94 dB   (ติดปัญหาความหน่วงเวลา)
3. NLMS + Delay Compensation (Lag=122): 69.32 dB   (🏆 ตัดเสียงสะท้อนเงียบกริบสมบูรณ์แบบ!)
================================================================================
```
* **การพิสูจน์:** การชดเชย Delay ช่วยดันค่า ERLE เพิ่มขึ้นถึง **+54.38 dB**

## 🗣️ 6.2 การทดลองสถานการณ์ที่ 2 (S2: Double-talk 2 คนพูดพร้อมกัน)

**เงื่อนไข:** มีเสียงสะท้อนจากลำโพง ($d[n]$) + เสียงคนพูดหน้าไมค์ ($v[n]$) เข้ามาพร้อมกัน  
**เป้าหมาย:** กำจัดเสียงก้องทิ้ง แต่ **ต้องเก็บเสียงคนพูดหน้าไมค์ไว้ให้ชัดเจน 100%**

```
[ สัญญาณไมค์รวม (Mixture) ]  = [ เสียงสะท้อนก้อง d[n] ] + [ เสียงคนพูดหน้าไมค์ v[n] ]
                                            │
                                  [ ผ่านตัวกรอง NLMS ]
                                            │
                                            v
[ สัญญาณเอาต์พุต e[n] ]      = [ ได้ยินเสียงคนพูดหน้าไมค์ v[n] ชัดเจน ไร้เสียงสะท้อน ]
```

* **ผลลัพธ์เชิงคุณภาพ:**
  - เสียงสะท้อนของ Far-End หายไปจนหมดสิ้น
  - เนื้อเสียงของ Near-End คงรูป Formants ครบถ้วน ไม่บี้แบน ไม่เพี้ยน

## 🚶‍♂️ 6.3 การทดลองสถานการณ์ที่ 3 (S3: มีการขยับเปลี่ยนตำแหน่ง)

**เงื่อนไข:** ผู้พูดหรือไมโครโฟนขยับตำแหน่งกลางคัน (ผลตอบสนองห้อง $h[n]$ เปลี่ยนที่วินาทีที่ 2.5)  
**เป้าหมาย:** ทดสอบความสามารถในการปรับตัวและลู่เข้าใหม่ (Tracking & Re-convergence)

```
Error squared (e^2[n])
  ^
  |  ช่วงที่ 1: ลู่เข้าสมบูรณ์        จุดเปลี่ยนตำแหน่ง (t=2.5s)
  |  *                              * (Error กระโดดขึ้นชั่วคราว)
  |   \                            / \
  |    \                          /   \___  ช่วงที่ 2: Re-converge กลับมาเงียบ
  +-----\------------------------/--------\---------------------------> เวลา (s)
  0                              2.5      3.0                        5.0
```

* **ผลการทดสอบ:**
  - ตัวกรองเกิด Error พุ่งขึ้นชั่วคราว ณ วินาทีที่เกิดการเคลื่อนที่
  - NLMS ใช้เวลาเพียง **0.3 - 0.5 วินาที** ในการคำนวณและปรับตัวเข้าสู่สภาวะเงียบสงบอีกครั้ง

## ❓ ช่วงถาม-ตอบ 5 นาที (Q&A Defense Master Sheet)

### คลังแนวทางการตอบคำถามอาจารย์ผู้สอน (เตรียมพร้อมรับมือทุกประเด็น):

1. **ถาม: ทำไมถึงไม่ใช้ `np.argsort()` หาความถี่เด่นของเสียงพูด?**
   - **ตอบ:** เสียงพูดมนุษย์มีลักษณะเป็นเนิน Formants กว้างตามสรีระคอหอย ไม่ใช่ Sine Wave เดี่ยวๆ หากใช้ `argsort` จะได้เฉพาะ bin สัญญาณที่อยู่ติดกัน การใช้ **Savitzky-Golay Smoothing** ร่วมกับ **Dynamic Threshold และ `find_peaks`** จึงเป็นวิธีที่ถูกต้องตามหลักสรีรศาสตร์เสียงครับ
2. **ถาม: ทำไมค่า ERLE ของ LMS ธรรมดาถึงได้แค่ 9.05 dB แต่ NLMS ได้ถึง 69.32 dB?**
   - **ตอบ:** เพราะ LMS ใช้ค่า $\mu$ คงที่ ทำให้ต้องตั้งค่าน้อยๆ เพื่อกันตัวกรอง Diverge ส่งผลให้ลู่เข้าช้ามาก แต่ NLMS มีการ Normalize ด้วยกำลังของอินพุต ทำให้ตั้ง Step-size ได้เต็มที่ และเมื่อบวกกับการชดเชย Bulk Delay 122 จุด ทำให้แท็ปทั้งหมดของตัวกรองนำไปใช้จำลองหางเสียงสะท้อนได้อย่างเต็มประสิทธิภาพครับ
3. **ถาม: ถ้าในชีวิตจริงคนพูดหน้าไมค์เสียงดังมาก ตัวกรองจะเพี้ยนไหม? (Double-Talk Problem)**
   - **ตอบ:** ตัวกรองอาจพยายามเรียนรู้เสียงคนพูดหน้าไมค์เข้าไป ซึ่งในระบบอุตสาหกรรมจริงจะแก้ด้วยการติด **Double-Talk Detector (DTD)** เช่น Geigel Algorithm เพื่อคอยแช่แข็งค่าน้ำหนัก (Freeze Weights) ชั่วคราวเมื่อตรวจพบว่ามีคนพูดแทรกครับ
